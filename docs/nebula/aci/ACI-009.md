# ACI-009 — ADE Live AI Performance Analytics & Recommendations
**Product:** Accretion Disk Engine (ADE)
**QEN:** Social Engine Build QEN
**Execution:** AIA / CAE — Local
**Branch:** `feature/aci-009`
**Type:** Product Capability
**Implementation Changes:** AUTHORIZED
## Current Truth
ADE already implements live AI content generation.
Do **not** rebuild or replace that capability.
Current analytics uses deterministic logic over manually captured performance metrics.
The missing capability is **live AI-assisted performance analysis and recommendation generation**.
## Mission
Allow ADE to analyze actual stored social-content performance evidence with live AI and provide the Operator with understandable, evidence-grounded recommendations for improving future content and increasing social-media viewership and online presence.
Implement:
**Goal + Content + Results → Live AI Analysis → Recommendation**
This ACI implements one capability:
**Live AI performance analytics and recommendations.**
## 1. Reuse Existing AI Infrastructure
Reuse the existing validated AI-provider boundary from the live-AI Draft capability wherever appropriate.
Do not create a second unnecessary AI architecture.
Keep credentials server-side and preserve existing security/configuration practices.
## 2. Analytics Inputs
Provide the AI only with relevant persisted ADE evidence, including where available:
Goal; Campaign; Source/content context; publication; views/reach; reactions; comments; shares; clicks; Audience Network movement; meaningful conversations; leads; other implemented performance metrics.
Preserve relationships between the evidence being analyzed.
## 3. AI Analysis
Allow the Operator to request AI analysis of available performance data.
ADE should help answer questions such as:
* What content appears to be performing best?
* What appears to be increasing viewership?
* What content produces meaningful engagement?
* Is the Goal progressing?
* What patterns appear across available content?
* What should the user try next?
AI must distinguish observed evidence from interpretation.
It must not invent missing metrics or business outcomes.
## 4. Recommendations
Produce concise, actionable recommendations grounded in the stored evidence.
Example structure:
**Observed:** what happened.
**Meaning:** reasonable interpretation of the evidence.
**Recommended Next Action:** what the Operator should consider doing next.
Recommendations remain advisory.
The Operator retains decision authority.
## 5. Evidence Traceability
The Operator should be able to understand what evidence produced a recommendation.
Do not create unexplained AI conclusions disconnected from ADE's stored metrics/content.
Where practical, associate the recommendation with the relevant:
**Goal / Campaign / Content / Results**
## 6. Analytics UI
Integrate live AI analysis into the existing Analytics/Intelligence experience.
The Operator should not need to export ADE data, open an external AI interface, manually construct a prompt, paste metrics, or copy the recommendation back.
Keep the UI focused on decisions rather than exposing raw prompt engineering.
## 7. Preserve Deterministic Analytics
Do not unnecessarily delete the existing deterministic analytics capability.
Use it as reliable baseline computation where useful.
Live AI should add interpretation and recommendations rather than replacing straightforward calculations with AI.
## 8. Failure Handling
If live AI analytics is unavailable:
* preserve stored metrics;
* preserve deterministic analytics;
* clearly report that AI analysis is unavailable;
* do not generate fake AI recommendations;
* do not break the rest of ADE.
Validate at least one AI-analysis failure condition.
## 9. Validation Scenario
Use persisted, clearly identified test performance data associated with multiple content items.
Prove:
**Goal → Campaign/Content → Results → Live AI Analysis → Evidence-Grounded Recommendation**
Use differing performance results so the AI has meaningful evidence to compare.
Confirm the resulting recommendation references actual stored evidence rather than invented performance.
## 10. Regression
Confirm ACI-009 does not break Sources, live AI Draft generation, manual Draft creation, Review/Approval, Publishing Queue, Goals, Campaigns, manual metrics, or provenance.
Do not rebuild these capabilities.
## 11. README
After successful validation, update implemented-capability truth to state that ADE provides live AI-assisted performance analysis/recommendations.
Continue distinguishing real platform analytics from manually entered performance data.
Do not imply Meta automatically supplies metrics if it does not.

* archive it under `/docs/nebula/acr/`;

Do not create another ACI numbering collision.
## Non-Goals
Do not implement:
* real Facebook/Meta metrics ingestion;
* real Facebook publishing;
* autonomous content approval;
* autonomous campaign execution;
* predictive performance guarantees;
* new content-generation capability;
* multi-provider AI orchestration;
* unrelated UI redesign.
## Completion Condition
ACI-009 is complete when:
> **ADE can use its live AI capability to analyze persisted social-content performance evidence and return useful, evidence-grounded recommendations that help the Operator decide how to improve future content, while retaining deterministic analytics and human decision authority.**
