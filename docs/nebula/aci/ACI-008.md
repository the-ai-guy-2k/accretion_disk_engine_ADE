# ACI-008 — ADE Live AI Content Generation
**Product:** Accretion Disk Engine (ADE)
**QEN:** Social Engine Build QEN
**Execution:** AIA / CAE — Local
**Type:** Product Capability
**Implementation Changes:** AUTHORIZED
## Mission
Replace ADE's mock/manual content-generation boundary with **real AI-assisted social-media content generation**.
The Operator should be able to select real source material and have ADE generate an editable social-media draft while preserving the existing human-approval workflow.
Core capability:
**Source → Live AI Generation → Draft → Human Review**
This ACI implements **content generation only**.
AI analytics/recommendations remain a separate capability.
## 1. Preserve Existing ADE
Do not redesign or rebuild the existing product.
Preserve the validated workflows established through previous ACIs, including:
**Goal → Campaign → Source → Draft → Review → Approval → Queue → Publication/Result**
Live AI generation must fit into the existing architecture.
## 2. AI Provider Boundary
Implement a clean provider abstraction so ADE's core workflow is not tightly coupled to one AI vendor.
The application should be able to:
* send approved source/context to an AI provider;
* receive generated content;
* handle provider errors;
* preserve generation status;
* return the generated content into ADE as a Draft.
Do not expose API credentials to the browser or repository.
## 3. Source-Grounded Generation
AI generation must use selected ADE Source material.
ADE should provide the model enough context to generate useful social content while maintaining source provenance.
The AI must not be instructed to invent:
* customers;
* results;
* revenue;
* metrics;
* endorsements;
* partnerships;
* completed work;
* product capabilities.
Generated content remains a **draft**, not established truth.
## 4. Operator Generation Controls
Keep controls useful but simple.
Allow the Operator to provide appropriate generation direction such as:
* target social platform;
* purpose/objective;
* tone;
* desired content length or format;
* optional additional instruction.
Do not build a giant prompt-engineering interface.
The experience should remain product-oriented.
## 5. Generate Draft
From the ADE UI, the Operator should be able to:
**Select Source**
→ **Generate with AI**
→ **Receive Draft**
The generated Draft must:
* persist in ADE;
* retain Source provenance;
* remain editable;
* identify that AI assisted its creation;
* enter the existing Review workflow.
## 6. Human Approval Boundary
AI-generated content must **never automatically publish**.
Preserve:
**AI Draft → Human Review/Edit → Approve/Reject**
Only approved content may continue toward the Publishing Queue.
## 7. Failure Handling
Handle AI-provider failure cleanly.
Examples:
* missing credentials;
* provider unavailable;
* timeout;
* malformed response;
* generation failure.
The UI should give the Operator an understandable failure state.
A failed generation must not create a falsely successful Draft.
## 8. Configuration
Use secure environment configuration for AI credentials.
Provide/update `.env.example` with variable names only.
Do not commit real secrets.
Document:
* provider configuration;
* required environment variables;
* local setup;
* behavior when AI is unavailable.
## 9. UI Integration
Integrate generation naturally into the existing **Create** workflow.
The Operator should not need to leave ADE, manually use another AI interface, copy the response, and paste it back.
The point of this capability is to remove that manual work.
## 10. Validation
Use real, non-sensitive test Source material.
Validate:
**Source**
→ **Live AI request**
→ **AI-generated Draft**
→ **persist**
→ **edit**
→ **Review**
→ **approve/reject**
Confirm Source provenance remains intact.
Also validate at least one AI failure condition.
## 11. Regression
Verify the existing ADE workflow still functions after AI integration.
Do not allow AI integration to break:
* manual Draft creation;
* Review;
* Approval;
* Publishing Queue;
* Goals;
* Campaigns;
* Results.
## 12. README
Update README implemented-capability truth after validation.
Describe live AI content generation as implemented **only if the live provider path is successfully proven**.
Keep future AI analytics clearly separated from implemented AI content generation.
